The whole idea
On a phone? Arrived from Google? Closed it on Tuesday? if ($visitor->…)  /* on the server */ Blaster never asks the server that. data-blaster-config  /* in the browser */

Anything that varies per visitor rather than per request cannot be decided on the server without either defeating your page cache or keeping a record of the person. So the server sends every bar that could apply, hidden, and the browser picks the one that wins.

Dismissal

Editing it
brings it back

Editing a bar is how you say “this is a new thing to say”.

  • Every save bumps the bar’s version
  • A dismissal is recorded against the version it dismissed
  • So an edit re-shows it to everyone who closed the old one
Before the edit
Version 4  ·  dismissed
Closed on a Tuesday, remembered for seven days, and gone from that visitor’s pages until the following week.
After the edit
Version 5  ·  shown again
The stored dismissal is cleared along with the view count. A stale dismissal quietly suppressing a new announcement is the failure nobody notices until the announcement matters.

The numbers

Counts that
describe nobody

Three integers per bar, per site, per day. That is the whole record.

  • No event rows, no identifiers, no addresses, no sessions
  • Which answers how many times, and never how many people
  • For a notification bar, that is the right way round
